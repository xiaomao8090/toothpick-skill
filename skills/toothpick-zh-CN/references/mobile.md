# 移动端

适用：iOS / Android App、小程序、H5、移动网页。

移动端的核心限制：**屏幕小、用手指点、常常单手、注意力碎片化**。

## 尺寸

- 设计基准宽度 375pt（iPhone）/ 360dp（Android），同时检查 320 和 430 宽度。
- 点击区域 ≥ 44×44pt（iOS）/ 48×48dp（Android），相邻可点元素之间至少留 8px。
- 正文 16~17px（iOS 默认 17pt），最小不低于 12px。输入框文字 ≥ 16px，否则 iOS Safari 聚焦时会自动放大页面。
- 左右边距 16~20px。

## 安全区

- 刘海、灵动岛、底部横条区域不能放内容和按钮。
- 网页用 `env(safe-area-inset-*)`，并在 viewport 里加 `viewport-fit=cover`。
- 底部固定按钮要加上底部安全区的高度。

## 布局与导航

- 主要导航放底部标签栏（3~5 项），因为单手拇指够得到。
- 最主要的操作放在屏幕下半部分。
- 返回：iOS 支持左边缘右滑返回，Android 支持系统返回键/手势，不要拦截。
- 列表优先，卡片其次。移动端卡片套卡片尤其浪费空间。
- 长表单分步骤，每步只问几个问题。

## 交互

- 没有悬停（hover）：所有通过悬停显示的东西都要换成可点击或直接显示。
- 按下要有即时反馈（变暗、缩小 0.97 或水波纹），100ms 内出现。
- 常用手势：下拉刷新、左滑操作列表项、长按出菜单。手势操作同时要有可见的按钮作为备选。
- 弹窗优先用底部弹出面板（bottom sheet），比居中弹窗更好单手操作。
- 输入时根据内容调出合适的键盘：`inputmode="numeric"` / `type="email"` / `type="tel"`。
- 键盘弹出时，当前输入框和提交按钮不能被遮住。

## 平台差异

| | iOS | Android |
|---|---|---|
| 字体 | SF Pro / 苹方 | Roboto / 系统中文字体 |
| 标题栏 | 标题居中（大标题可左对齐） | 标题左对齐 |
| 返回 | 左上角返回 + 边缘滑动 | 系统返回 |
| 主操作 | 导航栏右上角或底部 | 可用悬浮按钮（FAB） |
| 开关、选择器 | 系统样式 | Material 样式 |

做原生 App 时尽量遵循各自平台习惯；做跨平台或 H5 时，选一套统一风格，但返回逻辑要符合系统。

## 性能感知

- 骨架屏代替转圈。
- 列表图片先显示占位色块（取图片主色更好）。
- 操作先在界面上生效，再后台同步（乐观更新），失败了再提示。
- 弱网和离线时给出明确提示，已加载的内容仍可浏览。

## 小程序 / H5 额外注意

- 小程序遵循平台的胶囊按钮位置，右上角不要放自己的按钮。
- H5 页面禁止双击缩放导致的布局问题，但不要禁止用户手动缩放（影响无障碍）。
- 横屏时布局不能崩。
