# 做工细节

好界面很少靠某一个大决定，而是很多小细节叠起来的。下面是最容易被 AI 忽略、但一眼就能看出"做没做过"的地方。

整理自几个开源项目，原文更全，值得直接读：
- Vercel：Web Interface Guidelines（https://github.com/vercel-labs/web-interface-guidelines）
- Jakub Krehel：make-interfaces-feel-better（https://github.com/jakubkrehel/make-interfaces-feel-better）
- Paul Bakaus：impeccable 的 craft-floor（https://github.com/pbakaus/impeccable）

改细节时，用项目已有的样式写法（Tailwind 项目就用 Tailwind，纯 CSS 就用 CSS），不要为了一个小修改引入第二套样式体系。

## 表面：圆角、阴影、边框

- **嵌套圆角要同心**：外层圆角 = 内层圆角 + 内边距。内外用同一个圆角是最常见的"看着别扭"的原因。
- **阴影表示高度，边框表示结构**：只为了显出层次的边框，换成多层半透明阴影；表示分隔、选中、焦点的边框保留。
- **层次只用一种手段**：要么边框，要么阴影。1px 边框下面再垫一层大面积柔和阴影，会变成"幽灵卡片"。
- **阴影至少两层**：一层模拟环境光（大而淡），一层模拟直射光（小而实）。阴影要有偏移和模糊，零偏移的彩色光晕是装饰，不是深度。
- **半透明边框更清晰**：如 `rgba(0,0,0,.08)`，在不同底色上都自然。
- **图片加极淡的描边**：浅色下 `rgba(0,0,0,.1)`，深色下 `rgba(255,255,255,.1)`，用纯黑 / 纯白的透明度，不要用带色的灰，否则看起来像脏边。
- **有色背景上**，边框、阴影、次要文字要往同一个色相偏，不要用灰色。

## 对齐与排版

- **每个元素都要对齐到某个东西**：网格、基线、边缘或视觉中心，不要有"随便放"的位置。
- **视觉对齐优于几何对齐**：带图标的按钮、播放三角形、不对称的图标，几何居中往往看着偏，需要手动微调 1–2px。
- **图标和文字并排时平衡粗细**：常规字重（400）配 1.5px 线宽的图标，半粗（600）配 2px。一个界面只用一套图标库，不混用。
- **标题用 `text-wrap: balance`**，正文用 `text-wrap: pretty`，避免一行只剩一个字。
- **数字会变化或需要比较时**用 `font-variant-numeric: tabular-nums`。
- macOS 上可以给根元素加 `-webkit-font-smoothing: antialiased`，文字更清爽。
- 用省略号字符"…"而不是三个点"..."。
- 数字和单位之间用不换行空格：`10&nbsp;MB`。
- 标题上方留的空间要比下方多，让标题和它下面的内容成为一组。

## 浏览器自带的部件

模型最常漏掉、也是最便宜的"做过"信号：这些部件不是你画的，但会随页面一起出现。
- 文字选中颜色：`::selection`
- 输入光标颜色：`caret-color`
- 滚动条（深色界面尤其要处理）
- 焦点框：用 `:focus-visible`，不要被吸顶栏挡住
- 链接下划线位置：`text-underline-offset`
- 深色主题设置 `color-scheme: dark`，让滚动条和原生控件跟着变深
- `<meta name="theme-color">` 和页面背景一致
- Windows 上原生 `<select>` 要显式设置背景色和文字色

## 交互

- **按下有反馈**：按钮按下时 `scale(0.96)` 左右，不要小于 0.95。
- **悬停、按下、焦点时对比度要比平时更高**，而不是更低。
- **点击区域**：触屏至少 44×44px，桌面密集界面至少 40×40px（WCAG 最低 24px）。视觉元素小的话，用伪元素扩大点击范围。两个元素的点击区域不要重叠。
- **能点的地方看起来就能点，看起来能点的地方就真的能点**，不留"死区"。
- **导航用真正的链接** `<a>`，这样 Ctrl/⌘+点击、中键新标签页才能用。
- **状态放进 URL**：筛选、标签页、分页、展开的面板，刷新和分享后还在。
- **加载中的按钮**保留原文字，旁边加加载指示；转圈或骨架屏延迟约 150–300ms 才出现，出现后至少显示约 300–500ms，避免闪一下。
- **骨架屏和最终内容的布局完全一致**，避免跳动。
- **能撤销就不要确认框**；不能撤销的危险操作才二次确认。
- **不需要打断用户的任务不要用弹窗**。
- **提示气泡**：一组提示里第一个延迟出现，后面的不延迟。
- **每个页面都有下一步或返回的路**，没有死胡同。

## 动效

- 只给 `transform` 和 `opacity` 做动画最流畅；永远不写 `transition: all`，写清楚要过渡的属性。
- 交互状态变化用 CSS transition（可以被打断），只播放一次的分段动画才用 keyframes。
- 退出动画比进入更轻：小幅位移就够，不要整个高度滑出。
- 高频操作不加自定义动画，每次触发都在消耗注意力。
- 动画不能是唯一的反馈，状态变化同时要有颜色、图标或文字。
- 首次加载不要让所有元素都播放进场动画；分段进场只用在很少出现的重要时刻，每段间隔约 100ms。
- 检查动效时可以在浏览器动画面板里放慢到 10% 看，慢速下别扭的地方，正常速度下也是"说不出的不对"。

## 表单

- 每个输入框都有 `<label>`，点击 label 能聚焦输入框。
- 只有一个输入框时，回车提交；多行文本框里 ⌘/Ctrl+回车提交，回车换行。
- 不要阻止粘贴，不要拦截按键（只接受数字的框也让人输入，然后提示错误）。
- 提交按钮不要提前禁用，让用户提交后看到具体哪里没填。
- 错误显示在字段旁边，提交后自动聚焦到第一个错误。
- 设置正确的 `type`、`inputmode`、`autocomplete`，手机上会弹出合适的键盘、能自动填充。
- 占位符写示例值，如"+86 138 0000 0000"。
- 手机上输入框字号至少 16px，否则 iOS Safari 会自动放大页面。
- 有未保存的修改时，离开前提醒。

## 内容与文案

- 能在页面上直接解释的，不要藏进提示气泡。
- 页面 `<title>` 反映当前内容。
- 不只靠颜色传达状态，同时有文字或图标。
- 纯图标按钮要有 `aria-label`。
- 日期、时间、数字、货币按用户的地区格式显示；同一处的金额要么都带两位小数，要么都不带。
- 布局要经得起很短、正常、很长三种内容。
