# 配色

## 思路

- **先定灰阶，再定功能色**。大厂页面 90% 以上是黑白灰（见 `benchmarks.md`），彩色只出现在需要用户注意的地方：主按钮、链接、状态。
- **灰色可以是纯中性的**。Vercel、ChatGPT 用的都是纯中性灰；GitHub 是极轻的冷灰。"灰色必须带暖色调"之类的说法没有依据。重要的是整套灰阶统一。
- **颜色从产品的世界里来**。一个茶饮品牌、一个银行、一个儿童应用，颜色的来源应该完全不同。不要每次都拿同一套"有品位"的配色。
- **颜色要干净**。脏、闷、发灰的颜色（低饱和的棕、土黄、暗红混在一起）显得旧和廉价，除非品牌本身就是复古调性。
- **少即是多**。一屏里出现的彩色超过三种时，问问自己每一种在表达什么。
- **用 4–6 个具名色值写方案**：背景、主要文字、次要文字、边框 / 分隔、功能色，必要时加一个状态色。

## 常见问题

- 强调色到处都是 → 失去了"强调"的意义
- 浅色界面用纯黑 #000 大段文字配纯白底 → 对比过强、刺眼；大厂多用 #171717、#0D0D0D、#1F2328 这类近黑
- 边框用深色 → 页面变成线框图；参照里的边框都是 #EBEBEB、#D1D9E0 这类浅灰，或者 rgba(0,0,0,.08) 的细环
- 阴影太重 → 参照里的阴影透明度普遍只有 4%–8%
- 只靠红绿区分信息 → 色弱用户看不出来，加图标或文字
- 对比度不够 → 正文至少 4.5:1，小字争取 7:1

## 深色模式

深色模式不是反色，要单独设计（细节见 `big-company-details.md` 第一节）：
1. 背景用深灰而不是纯黑（#121212 左右），层级越高越亮
2. 阴影在深色下基本看不见，层级靠表面亮度差和半透明白色细线
3. 文字不用纯白，次要文字降低亮度
4. 彩色降低饱和度、适当提亮
5. 白字在黑底上显粗，正文字重可以稍微调细
6. 白底图片稍微压暗

### 实现
```css
:root {
  --bg: #FFFFFF; --surface: #FAFAFA; --text: #171717;
  --text-2: #5C5C5C; --border: rgba(0,0,0,.08); --accent: /* 按项目选 */;
}
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --bg: #121212; --surface: #1A1A1A; --text: #EDEDED;
    --text-2: #A1A1A1; --border: rgba(255,255,255,.1); --accent: /* 降饱和版本 */;
  }
}
:root[data-theme="dark"] { /* 同上，供手动切换 */ }
```
- 组件里只引用变量，不写死色值
- 默认跟随系统；提供手动切换时，用户的选择优先
