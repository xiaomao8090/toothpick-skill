锁分析
对每条 DDL 标出会拿到的锁，结合表的真实行数估算阻塞时间。超过你设定的上限，CI 直接失败。

        
影子库演练
用生产库的结构和统计信息拉起一个临时实例，把迁移真实跑一遍，跑完即销毁，不碰生产数据。

        
回滚草稿
没写 down 迁移时，根据 up 语句生成回滚脚本草稿，并标出删列这类无法自动回滚的操作。

      

    

  


  

    

      

        
接入现有项目

        
不需要改动任何迁移文件。支持 Flyway、golang-migrate、Prisma 和 Rails 生成的 SQL。

      

      
    
        
  1. 安装（macOS / Linux），或者使用 Docker 镜像
    brew install tern-db/tap/tern
docker run --rm ghcr.io/tern-db/tern:0.9 --help
    2. 
        
  2. 在项目根目录生成配置，指定迁移文件的位置
    tern init --migrations ./db/migrations
    3. 
        
  3. 连接一个只读副本，运行第一次分析
    export TERN_DSN="postgres://readonly@replica:5432/shop"
tern plan
    4. 
        
  4. 加入 CI，风险超过上限时阻止合并
    # .github/workflows/migrate.yml
- run: tern plan --max-lock 2s --format github
    5. 
      

      
目前还不支持：MySQL 和 SQLite（MySQL 在计划中），存储过程内部的 DDL，Windows 原生运行（可以用 WSL 或 Docker）。
