上生产之前，
先看清这次迁移会锁哪张表、锁多久。

tern 读取你的迁移文件，在执行前分析每条语句会拿什么锁、扫描多少行，并在一个影子库上完整演练一遍。有风险的地方，它会直接告诉你怎么改写。

$ brew install tern-db/tap/tern
5 分钟上手 →
~/projects/shop-api — tern plan

      

    

  


  

    

      
它做什么

      
三件你本来要手动做、而且经常忘记做的事

      
tern 不替代你的迁移框架。它读 Flyway、golang-migrate、Prisma、Rails 生成的 SQL，在它们执行前插一道检查。


      

        01
        

          
锁分析

          
对每条 DDL 标出会获取的锁级别，结合 pg_class 的行数估算阻塞时间。ACCESS EXCLUSIVE 超过阈值会直接让 CI 失败。

        


$ tern plan --max-lock 2s
✗ 0042_add_status.sql:3
  ALTER TABLE orders ADD COLUMN status text
  NOT NULL DEFAULT 'paid';
  锁: ACCESS EXCLUSIVE · 预计 41s (8.2M 行)

      


      

        02
        

          
影子库演练

          
用生产库的表结构和统计信息拉起一个临时实例，把迁移真实跑一遍，记录每一步的耗时和锁等待，跑完即销毁。

        


$ tern rehearse --from prod-replica
✓ 克隆结构与统计信息      3.1s
✓ 0041_index_sku.sql      12.4s
✓ 0042_add_status.sql      0.2s
  影子库已销毁

      


      

        03
        

          
每一步都能回滚

          
没有写 down 迁移？tern 会根据 up 语句生成一份回滚脚本草稿，并标出无法自动回滚的语句（比如删列），让你在合并前就决定怎么办。

        


$ tern rollback --dry-run 0042
  ALTER TABLE orders DROP COLUMN status;
! 0039_drop_legacy.sql 无法自动回滚
  原因: 删除列的数据不可恢复

      

    

  


  

    

      
和手动流程比

      
它补上的是 code review 看不出来的那部分

      
SQL 写得对不对，同事能看出来；它在一张 800 万行的表上会锁多久，靠眼睛很难判断。

      

        
检查项人工 reviewtern

        
          
语法和逻辑可以可以

          
锁级别靠经验，容易漏逐条标注

          
按真实行数估算耗时需要手动查自动读取统计信息

          
在接近生产的环境演练通常跳过tern rehearse

          
改写建议—给出可直接复制的 SQL

        
      

    

  


  

    

      
快速开始

      
接进现有项目，不改任何迁移文件

      
    
        
  1. 
          
    
            
    安装（macOS / Linux），或者直接用 Docker 镜像
    

    $ brew install tern-db/tap/tern
$ docker run --rm ghcr.io/tern-db/tern:0.9 --help
    
          
    
        
    2. 
        
  2. 
          
    
            
    在项目根目录生成配置，告诉它迁移文件在哪
    

    $ tern init --migrations ./db/migrations
✓ 已创建 tern.toml
    
          
    
        
    3. 
        
  3. 
          
    
            
    连一个只读副本，跑第一次分析
    

    $ export TERN_DSN="postgres://readonly@replica:5432/shop"
$ tern plan
    
          
    
        
    4. 
        
  4. 
          
    
            
    加到 CI 里，风险超过阈值就阻止合并
    

    # .github/workflows/migrate.yml
- run: tern plan --max-lock 2s --format github
    
          
    
        
    5.

    • 
          
  • 存储过程内部的 DDL 分析
    • 
          
  • Windows 原生二进制（可以用 WSL 或 Docker）
