tern第一话

四十一秒给 821 万行的表加一列，所有请求排队 41 秒。

0042_add_public_id.sqlALTER TABLE orders ADD COLUMN public_id uuid NOT NULL DEFAULT gen_random_uuid();

tern 在迁移执行前算出每条语句会拿什么锁、挡住多久，并给出不锁表的改写方案。开源，支持 PostgreSQL 12 到 17。

brew install tern-db/tap/tern

其二　tern合并之前

tern fix 0042 把一条语句拆成六步。重的锁只在改表结构的瞬间出现，费时间的回填和校验都不挡读写。

3

设定资料八把锁

PostgreSQL 的表锁有八种，从轻到重排在下面。网点越密，锁越重。会挡写的有四种，连读都挡的只有最后一种，也就是第一话里的那一把。

每张卡下面的八个格子和卡片的排法一样，从右往左依次对应这八种锁；黑格表示两把锁不能同时拿：后来的那个要排队。

4

分镜接入四步

接入现有项目，不改任何迁移文件。支持 Flyway、golang-migrate、Prisma 和 Rails 生成的 SQL。

  1. 镜号画面说明
  2. 1
    brew install tern-db/tap/tern
docker run --rm ghcr.io/tern-db/tern:0.9 --help

    安装。macOS 和 Linux 用 Homebrew，也可以直接用 Docker 镜像。

  3. 2
    tern init --migrations ./db/migrations

    在项目根目录生成配置，指向迁移文件所在的目录。

  4. 3
    export TERN_DSN="postgres://readonly@replica:5432/shop"
tern plan

    连一个只读副本，跑第一次分析。它只读表结构和统计信息，不碰生产数据。

  5. 4
    # .github/workflows/migrate.yml
- run: tern plan --max-lock 2s --format github

    加进 CI。有语句的锁超过 2 秒，退出码为 1，合并会被拦下。

后记

这一话里的数字，来自一张 821 万行、每秒约 70 次读写的示例表。你的表有多大、有多忙，要自己跑一次 tern plan 才知道。

tern 目前还做不到的事：只支持 PostgreSQL 12 到 17；MySQL 和 SQLite 还不支持，MySQL 在计划中；存储过程内部的 DDL 读不出来；Windows 上要通过 WSL 或 Docker 运行。

名字来自北极燕鸥，它每年迁徙约七万公里。
