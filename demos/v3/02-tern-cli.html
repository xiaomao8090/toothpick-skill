迁移文件锁影响行数挡住读写结果

            
              
0041_index_sku.sql
CREATE INDEX CONCURRENTLY idx_sku ON products (sku)
SHARE UPDATE EXCLUSIVE1,204,8800 秒通过

              
0042_add_public_id.sql
ALTER TABLE orders ADD COLUMN public_id uuid NOT NULL DEFAULT gen_random_uuid()
ACCESS EXCLUSIVE8,214,330约 41 秒超过 2 秒

            
          

        

        

          
默认值 gen_random_uuid() 每行都不一样，PostgreSQL 必须重写整张表。建议把 0042_add_public_id.sql 改写成下面六步，运行 tern fix 0042 可以直接生成：


ALTER TABLE orders ADD COLUMN public_id uuid;                          -- 只改表结构，约 20 毫秒
ALTER TABLE orders ALTER COLUMN public_id SET DEFAULT gen_random_uuid(); -- 新写入的行自动有值
UPDATE orders SET public_id = gen_random_uuid()
  WHERE id BETWEEN $1 AND $2 AND public_id IS NULL;                    -- 每批 1 万行，共 822 批，不挡读写
ALTER TABLE orders ADD CONSTRAINT public_id_nn
  CHECK (public_id IS NOT NULL) NOT VALID;                             -- 不扫表，约 10 毫秒
ALTER TABLE orders VALIDATE CONSTRAINT public_id_nn;                   -- 扫全表，但不挡读写
ALTER TABLE orders ALTER COLUMN public_id SET NOT NULL;                -- PostgreSQL 12+ 借上一步的约束跳过扫描

        

      

    

  


  

    

      

        
PostgreSQL 有 8 种表锁，只有一部分会挡住你的用户

        
tern 做的第一件事，就是给每条语句标上它会拿的锁。下面这张表可以随手查。

      

      

        

          

            
锁常见语句挡住读挡住写

            
              
ACCESS SHARESELECT不挡不挡

              
ROW SHARESELECT … FOR UPDATE不挡不挡

              
ROW EXCLUSIVEINSERT、UPDATE、DELETE不挡不挡

              
SHARE UPDATE EXCLUSIVECREATE INDEX CONCURRENTLY、VALIDATE CONSTRAINT、VACUUM不挡不挡

              
SHARECREATE INDEX（不加 CONCURRENTLY）不挡挡

              
SHARE ROW EXCLUSIVECREATE TRIGGER、部分 ADD FOREIGN KEY不挡挡

              
EXCLUSIVEREFRESH MATERIALIZED VIEW CONCURRENTLY不挡挡

              
ACCESS EXCLUSIVE大多数 ALTER TABLE、DROP、TRUNCATE、VACUUM FULL挡挡

            
          

        

      

      
"挡住读写"指挡住普通的 SELECT 和 INSERT / UPDATE / DELETE。锁本身拿得快不快，还取决于表上有没有长事务，tern 会一起检查。

    

  


  

    

      

        
接入现有项目，不改任何迁移文件

        
支持 Flyway、golang-migrate、Prisma 和 Rails 生成的 SQL。

      

      
    
        
  1. 安装（macOS / Linux），或者用 Docker 镜像
    brew install tern-db/tap/tern
docker run --rm ghcr.io/tern-db/tern:0.9 --help
    2. 
        
  2. 在项目根目录生成配置，指定迁移文件的位置
    tern init --migrations ./db/migrations
    3. 
        
  3. 连接一个只读副本，跑第一次分析
    export TERN_DSN="postgres://readonly@replica:5432/shop"
tern plan
    4. 
        
  4. 加进 CI，超过上限就阻止合并
    # .github/workflows/migrate.yml
- run: tern plan --max-lock 2s --format github
    5. 
      

      
目前还不支持：MySQL 和 SQLite（MySQL 在计划中），存储过程内部的 DDL，Windows 原生运行（可以用 WSL 或 Docker）。
