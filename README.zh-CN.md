# 牙签 Toothpick

一个让 AI 做界面时认出"AI 味"、避开常见缺陷的 skill。像牙签一样，把卡在设计里的 AI 味剔出来。提供中文和英文两个版本，Claude、Codex、DeepSeek 都能用。

![同一个咖啡店需求，左边是第一版 skill 的结果，右边是现在的](docs/coffee-v1-v3.png)

同一个需求："给一家每周烘焙的小咖啡店做官网"。左边是这个 skill 第一版做出来的：米色纸张、衬线字、暗红强调、超大期号，正是 AI 最常见的"有品位"打扮。右边是现在的版本：首屏放的是这家店本周三炉豆子的烘焙曲线。

## 它和其他设计 skill 的区别

**不提供风格库。** 很多设计 skill 会准备几十种风格、上百套配色让 AI 挑选，结果 AI 换来换去，还是在给页面套一套现成的戏服。这里不规定必须用什么、禁止用什么，只问一个问题：这个选择是为这个产品做的，还是换成任何产品你都会这么做？

**每条 AI 味都写了"什么时候可以用"。** 识别清单共 39 条，每条分三部分：表现是什么、为什么一眼像 AI、哪种情况下它其实是对的。AI 能判断，就不需要死记规则。

**参照来自实测。** 在浏览器里读取了 Vercel、GitHub、ChatGPT、Google、Linear 页面的实际样式：标题字重、灰色色值、阴影透明度、产品画面占多少面积。这些数据只作参照，不当模板。

**不拿假东西糊弄开发者。** 已有项目时先读项目再动手，界面上只出现项目真有的功能；接不了接口时，模拟数据集中放在一处，字段和真实接口一致；没接通的按钮不做成看起来能用。交付时附一份占位清单，写明哪些是模拟数据、哪些没接通、做了哪些假设。

**设计想法从客户本身来。** 动手前，先写下 8 到 12 个"只属于这个客户、竞争对手没有"的东西：名字的含义、所在的街道、用的材料、它的数字、它的限制。上面那条烘焙曲线，就是从这份清单里来的。

## 安装

中文版和英文版只装一个。两个版本的 `name` 都是 `toothpick`，内容相同，区别只是写给 AI 的说明用什么语言。

| 用在哪里 | 怎么装 |
|---|---|
| Claude Code | 把 `skills/toothpick-zh-CN` 复制到 `~/.claude/skills/toothpick`（所有项目都能用），或项目里的 `.claude/skills/toothpick` |
| Claude 应用 | 把 `skills/toothpick-zh-CN` 文件夹打包成 zip，在设置的技能页面上传 |
| Codex | 把 skill 文件夹放进项目，再把 `prompts/codex-agents.zh-CN.md` 里的那段话复制到项目根目录的 `AGENTS.md` |
| DeepSeek 和其他模型 | 打开 `prompts/toothpick.zh-CN.md`，复制分隔线以下的内容到系统提示词。这是一个可以单独使用的精简版 |

装好之后正常提需求就行，比如"做一个记账 App 的首页"。Claude 会根据描述自动调用这个 skill。

## 它让 AI 怎么做

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="docs/mindmap-zh-CN-dark.png">
  <img alt="牙签的结构：核心判断、AI 味识别、参照、七步流程、底线、用在哪" src="docs/mindmap-zh-CN-light.png">
</picture>

1. **先读项目，再判断页面模式**：已有项目时，先弄清楚项目真有哪些功能、组件、样式变量和数据字段。页面模式分说服（官网、落地页）、操作（后台、工具）、阅读（文档、文章）、展示（作品集），按页面判断，不按产品判断。
2. **盘点只属于这个客户的东西**，从里面找设计想法。
3. **营销页先写论证**：每个板块一行"主张和证据"，没有主张的板块删掉。
4. **写简短方案**：4 到 6 个色值、字体、布局思路，以及页面的主角是什么。
5. **自问是默认值还是选择**，对照识别清单检查。
6. **实现**：页面上展示产品界面时，用真实数据做成产品的一个片段，不用灰色色块。
7. **在实际尺寸下看成品**，一次看完一起改，最后去掉一件多余的装饰。

去掉装饰只是一半。另一半是补上实质内容：更大胆的字号对比、整块的颜色、真实的画面、写满内容的板块。否则页面会显得单薄。

## 识别清单节选

| 表现 | 为什么像 AI | 什么时候可以用 |
|---|---|---|
| 米色背景、衬线大标题、陶土色强调 | AI 被要求"有品位"时的固定答案 | 品牌确实有纸质、手工、出版物背景 |
| 近黑背景、一个荧光色、满屏等宽字体 | AI 对"极客"的固定想象，GitHub、Vercel、Linear 的官网都不这样做 | 等宽字体只出现在真正的代码里 |
| 每个标题上面一行全大写小标签 | 通常只是把标题再说一遍 | 它确实提供了分类或位置信息 |
| 不是步骤也编号 01 / 02 / 03 | 编号暗示先后顺序 | 内容真的是步骤或时间线 |
| 界面上出现项目里没有的功能 | 页面好看了，却误导了开发者 | 不适用 |
| 去掉了所有装饰，却什么都没补上 | 页面单薄，盲测中甚至不如有点 AI 味但内容丰富的页面 | 不适用 |

完整清单见 `skills/toothpick-zh-CN/references/ai-tells.md`。

## 三个网站，三个版本

这个 skill 是靠反复做同样三个网站改出来的。每一版的问题都写进了下一版的 skill。

![tern 的三个版本](docs/tern-v1-v2-v3.png)

![建筑事务所的三个版本](docs/architects-v1-v2-v3.png)

| 版本 | 当时 skill 的做法 | 结果 |
|---|---|---|
| 第一版 | 一套规则、一个风格方向库、"必须有一处记忆点" | 三个网站各中一种 AI 风格戏服：米色加衬线、近黑加琥珀色、黑色细线加零圆角 |
| 第二版 | 改成识别清单，加入大厂实测参照 | 干净、克制，但偏素，内容单薄 |
| 第三版 | 加入"盘点客户独有的东西"、"先写论证"、做工细节 | 首屏主角分别是烘焙曲线、锁时间线、可以逐期查看的改造平面图 |

三个版本的页面都在 `demos/`（第一版）、`demos/v2/`、`demos/v3/`，双击就能在浏览器里打开。品牌、人物和数据都是虚构的。上面的截图是在没有加载网络字体的环境里生成的，实际打开时字体会不一样。

## 局限

- **专业事实需要核对。** 第二版 tern 页面写了"加一个带常量默认值的非空列会锁表 41 秒"，这在 PostgreSQL 11 以后并不成立。AI 写技术细节、规范、数据时会出错，上线前要人工核对。
- **没有自动检测。** 有些开源 skill 带了检测脚本，可以在浏览器里自动查出 AI 味。这个 skill 只靠 AI 自己截图自评，换来的是不依赖任何运行环境、DeepSeek 也能用。
- **只覆盖界面设计和项目 README。** 插画、品牌标识、动画短片不在范围内。
- **示例网站只有中文。** 三个示例网站是用中文版 skill 做的，内容没有翻译。

## 参与改进

发现新的 AI 味，按"表现、为什么像 AI、什么时候可以用"的格式补进 `references/ai-tells.md`。中英文两个版本要在同一次提交里一起改，再在 `prompts/` 的两份精简版里各加一句。

## 参考来源

思路参考了以下项目，内容用自己的话重写，没有照搬原文：

- Anthropic 官方 frontend-design skill：判断"默认值还是选择"、AI 默认风格的识别、文案原则
- [impeccable](https://github.com/pbakaus/impeccable)：四种页面模式、改版和优化的区别、做工底线
- [taste-skill](https://github.com/Leonxlnx/taste-skill)：盘点客户独有的东西、先写论证、克制不等于空
- [make-interfaces-feel-better](https://github.com/jakubkrehel/make-interfaces-feel-better)：圆角、阴影、图标、动效的细节
- [Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines)：交互、表单、内容的细节
- 苹果、谷歌 Material、IBM Carbon、微软 Fluent、Ant Design 的官方设计规范

看过但没有采用：[UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 这类"风格库加配色库加字体库"的做法，原因见上面的"不提供风格库"。
