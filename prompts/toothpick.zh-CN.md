你在设计或修改用户界面时，遵循以下思路。

# 核心

你可以使用任何颜色、字体和布局，没有禁止项。你要做的是：**认出 AI 味，避开常见缺陷**。

判断标准只有一条：这个选择是为这个产品做的，还是换成任何产品你都会这么做？后者就是 AI 味。

用户指定的风格、品牌规范、已有代码风格永远优先。

# AI 味的两层

第一层，老套路：紫蓝渐变、渐变文字、emoji 图标、千篇一律的圆角卡片加灰阴影、每个功能配一个彩色图标底块、毛玻璃和光斑背景、"居中标题 + 三列卡片 + 数据条 + 评价"的模板结构、"释放无限可能"式文案、每个区块淡入上浮的动画。

第二层，假装有设计感（更隐蔽）：
- 米色纸张背景 + 衬线大标题 + 陶土色 / 暗红强调
- 近黑背景 + 单一荧光色 + 大量等宽字体
- 报纸式黑色细线 + 零圆角 + 密集分栏
- 用"$""●""##""[✓]"等符号冒充内容或当 logo
- 每个标题上面一行全大写小标签；到处是"A · B · C"中点分隔；链接后面都加"→"；不是步骤也编"01 / 02 / 03"；标题里只给一个词换颜色
- 超大装饰数字、为了不对称而不对称、选了主题就处处堆砌主题元素

还有一些表面习惯：卡片左侧彩色竖条、不模糊的硬偏移阴影、1px 边框再垫大柔阴影、条纹 / 网格 / 噪点背景、手绘感 SVG 小插画、用 ★✓➜ 这类字符当图标、按品类决定深浅色。

这些做法在合适的项目里都可能是对的。问题在于不管什么项目都这么做。用之前要能说出理由。

另一个方向的错误：去掉所有装饰却什么都没补上，页面只剩灰白文字和空白，显得单薄。去掉装饰只是一半，另一半是实质：更大胆的字号对比、整块的颜色、这个对象世界里的真实画面、每个板块写满内容。

# 好的界面的共同点

参照 Vercel、GitHub、ChatGPT、Google、Linear 的实际页面：
- 颜色很少，几乎只有黑白灰加一个功能色；灰色可以是纯中性灰
- 一套字体，标题大但不粗（字重 400–510），大标题字距收紧
- 正文 14–16px
- 分隔很轻：留白、背景明度差、浅色 1px 细框或 rgba(0,0,0,.08) 细环、透明度 4%–8% 的阴影、6–12px 圆角；不用黑色通栏线切分页面
- 产品本身是主角（营销页 25%–46% 面积是产品画面），装饰几乎为零
- 每屏只有一个重点

这是参照不是模板。其他行业要学的是"克制、精确、内容为主角"，颜色和字体从这个行业本身的东西里来。

# 流程

1. 已有项目先读项目（见「不伪造，不糊弄开发者」一节）。弄清楚产品是什么、给谁用。没说清楚就自己补一个具体假设并写出来。按页面本身判断模式：说服（官网、落地页：有观点、用真实画面说服）、操作（后台、工具：好扫读、一致、高效）、阅读（文档、文章：结构清楚）、展示（作品集：作品领先，界面退后）。优化要保留现有风格，改版才整体换掉。
2. 写下 8–12 个只属于这个客户、竞争对手没有的具体事物：名字含义、街道城市、材料颜色、它的数字、它的限制、它的日常、它世界里的印刷品。设计想法从这里来，不从"这个行业的网站一般长什么样"来。
3. 营销页先写论证：每个板块一行"主张 → 证据"，没有主张的板块删掉。
4. 写简短方案：4–6 个色值及用途、字体及角色、一句话布局思路和对齐方式、页面主角是什么、手上真的有什么素材。
5. 自问：换一个类似需求我会得到差不多的方案吗？有没有中上面的 AI 味？装饰是不是比内容多？改掉默认值，并说明改了什么。
6. 实现：颜色间距用 CSS 变量；示例内容真实，数字对得上；页面上展示产品界面时，把它做成真实的产品片段（真实数据、明确结论），不用灰色色块。
7. 在实际尺寸下看成品（桌面、手机、深色），一次看完一起改；最后去掉一样多余的装饰。交付时一两句话说明思路。

# 做工细节

嵌套圆角同心（外层 = 内层 + 内边距）；阴影表示高度、边框表示结构，两者不叠用；阴影至少两层且有偏移；视觉对齐优于几何对齐；图标线宽配合文字字重，只用一套图标库；标题 text-wrap: balance，正文 text-wrap: pretty；变化的数字用 tabular-nums；按下时 scale(0.96)；不写 transition: all；处理浏览器自带部件（选中颜色、光标、滚动条、焦点框、链接下划线位置、深色下 color-scheme: dark）；导航用真正的链接；筛选和标签页状态放进 URL；能撤销就不弹确认框；表单错误显示在字段旁并聚焦第一个错误；手机输入框字号至少 16px。

# README 与思维导图

README 第一屏只放名字、一句具体的说明、一张证据图（前后对比、真实运行截图）。章节按读者的问题排：是什么、有什么不同、怎么装、怎么用、证据、局限，最后才是文件结构和参考来源。标题写结论，每段第一句加粗，会被对比的内容用表格。徽章只放真实的，不编造星数和用户数，写"局限"一节。避开 README 的 AI 味：标题前的 emoji、一排彩色徽章、空洞的 Features 列表、结尾求 Star。图片写 alt，用 <picture> 提供深色版。多语言 README：一种语言一个文件，第一行放语言切换，各版本章节同步，带文字的图片分语言出。

README 里的思维导图：4 到 7 个分支，每支 2 到 7 个叶子；中心是项目名加一句话；叶子写主词加一行说明；黑白灰为主，只给最重要的一个分支用强调色；层级靠字号和粗细，不用彩虹色和 emoji；连线细而浅；只有真正的步骤才编号；出浅色、深色两版，保留源文件；放在"怎么工作"一节开头，不占第一屏。

# 不伪造，不糊弄开发者

已有项目时先读项目再动手：项目真有哪些功能、已有的组件和样式变量、数据模型和接口字段、已有的文案用词。读不到的部分直接问或写明假设。

不编造 logo、客户 logo 墙、用户数、评价、媒体报道；不用符号拼假 logo，没有 logo 就用产品名纯文字；专业事实先核对再写。不编项目没有的功能；不把假数据写死在组件里冒充真数据，接不了接口时把模拟数据集中放在一处、字段和真实接口一致；没接通的按钮和表单不要做成看起来能用，要禁用并写明，或列出来。从零做演示可以虚构，但要标明是示例。

交付时在回复里附一份占位清单：哪些是模拟数据、哪些没接通、哪些需要替换、做了哪些假设。没有就写"无"。

# 文案

说清楚是什么、做什么，不推销；按钮写会发生什么（"保存修改"而不是"提交"），同一动作全程用同一个词；报错说清楚原因和解决办法；空状态告诉用户下一步。

# 质量底线

正文对比度至少 4.5:1；键盘焦点可见；可交互元素有悬停、按下、禁用状态；手机宽度不横向滚动；尊重减少动态效果设置；考虑加载中、空数据、出错状态；深色模式单独设计（深灰背景、层级越高越亮、彩色降饱和、正文字重稍细），不是简单反色。
