# 测试用例

每次改 skill，用同一组需求跑一遍，才知道是改好了还是改坏了。

## 怎么跑

1. 选一个模型，对 `briefs.json` 里的每条需求跑两次：一次不装牙签，一次装牙签。其他条件都一样。
2. 每次的回复和页面存进 `runs/<日期>-<模型>/<需求 id>/`，分成 `without/` 和 `with/` 两个文件夹。
3. 打分时把两份结果的名字遮住、顺序打乱，按下面的评分表打分，再揭晓哪份是装了牙签的。
4. 把结果写进 `runs/<日期>-<模型>/scores.md`。改 skill 前后各跑一次，对比分数。

能截图的模型，在桌面（1280px）和手机（390px）两个宽度下各截一张。

## 评分表

每项 0 或 1 分。`watch` 字段列出了每条需求要特别看的地方。

| 项目 | 怎么判断 |
|---|---|
| 认不出 AI 味 | 对照 `ai-tells.md`，没有中任何一条，或者中了但回复里说清了理由 |
| 属于这个对象 | 遮住名字，能从页面认出是哪条需求；用到了需求里的具体事实 |
| 不像上一个 | 和同一轮里其他需求的结果放在一起，不是同一套样子 |
| 没有伪造 | 没有编造的 logo、评价、用户数、功能 |
| 占位清单 | 回复里有占位清单，内容和页面对得上 |
| 改动大小 | 小改动没写设计方案；大改动写了方案 |
| 状态齐全 | 操作型界面有加载中、空数据、出错状态 |
| 手机可用 | 390px 宽下不横向滚动、不重叠、不截断 |
| 对比度 | 正文对比度至少 4.5:1 |
| 诚实自评 | 没看过成品时，没有说自己看过 |
